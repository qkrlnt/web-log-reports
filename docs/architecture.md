# Архитектура

Тема: web-сервис генерации отчетов на основе журналов web-сервера.
Основание: лабораторные работы 3 и 4.

Планируемая цепочка: web-server → access.log → Fluent Bit → FastAPI →
валидация и хранилище → отбор → pandas → Jinja2 → WeasyPrint → PDF в браузере.
Запуск полной системы планируется через Docker Compose.

В уточнённом проекте лабораторной 4 источником журнала выбран Nginx,
постоянным хранилищем — SQLite с файлом `/data/logs.sqlite3` в томе данных.
Fluent Bit использует плагины Tail и HTTP. FastAPI вызывает LogParser
с проверкой Pydantic, затем сохраняет записи через SQLiteLogRepository
на стандартном модуле `sqlite3`.

ReportService получает выборку методом `select(period, filters)`, вызывает
AnalyticsService на pandas, формирует HTML шаблоном Jinja2
`templates/report.html` и PDF методом WeasyPrint `HTML.write_pdf()`.
Это проектная структура полной версии; текущее состояние прототипа описано ниже.

Текущий учебный прототип включает парсер, API приема строк и общие показатели.
Данные хранятся только в памяти одного процесса и теряются при перезапуске.
`POST /logs` принимает объект `{"lines": ["строка CLF"]}`.
Адаптация формата отправки Fluent Bit, постоянное хранилище, pandas,
генерация PDF, web-интерфейс и Docker Compose относятся к следующим инкрементам.
Наличие конфигурации CI не означает, что CI уже выполнялся на GitHub.

## Соответствие модулей

- `parser.py`: разбор записи и проверка формата.
- `analytics.py`: расчет базовых показателей.
- `main.py`: прием пакета и выдача статистики через HTTP.
- Будущие `storage.py`, `filters.py`, `reports/`, `templates/`, `static/`:
  хранилище, отбор, PDF и пользовательский интерфейс.

Новые модули добавляются по мере реализации задач, а не пустыми заглушками.
