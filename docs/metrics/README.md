## Как сохранить замер

1. Дождаться успешного CI на `main` после слияния этапа.
2. Поставить тег на проверенный commit и отправить его. Пример:

```powershell
git switch main
git pull --ff-only
git tag -a stage/increment-2 -m 'Second increment checkpoint'
git push origin stage/increment-2
```

3. Дождаться запуска Actions для тега. В Actions → нужный запуск → Artifacts
   скачать `quality-reports-<run_id>-<attempt>`, внутри найти `metrics.json`.
   Записать ссылку на запуск и SHA. Сохранить `coverage.xml`, `junit.xml`,
   `ruff.json`, `complexity.json` для проверки расчета.
4. Сохранить снимок как `docs/metrics/increment-2.json` отдельным docs-коммитом
   в новой ветке и слить через PR. Внутри JSON останется SHA измеренного кода;
   SHA docs-коммита будет другим, это нормально. Для следующего этапа повторить.
5. Заполнить таблицу отчета фактическими значениями. Пример колонок:
   этап, плановая/фактическая дата, SHA, pipeline, lint, CC mean/max,
   строки %, ветви %, passed/failed/errors/skipped, время тестов.

CI сохраняет артефакты на 30 дней. Git-коммиты снимков сохраняют историю независимо
от истечения артефактов. Теги контрольных точек не переносить на другие коммиты.
Снижение процента покрытия после добавления функций оценивается по изменению
покрытых и непокрытых строк, а не трактуется автоматически как регресс кода.

При событии pull_request Actions тестирует пробное слияние с main;
в metrics.json записывается SHA этого проверенного merge-коммита.
Для итоговых снимков этапов использовать запуск по тегу на main.
